Very simple guide: the tools behind Amigo

Written for Clarice. Plain words, small examples, and the order that usually makes sense.

1. The big picture

Amigo is an app (a website that can feel like an app on your phone). You keep the recipe for that app in one folder on your computer. When you change the recipe, you can save a snapshot (that’s Git), upload it to a safe copy online (GitHub), and tell the internet to show the latest version to anyone with the link (Vercel). You edit the recipe in Cursor, an editor that can help you think and type faster—like a smart notebook that suggests fixes.

Short analogy
  • Your project folder (E:\Amigo) = your kitchen where you cook.
  • Git = dated photos of each version of the dish (“what changed today?”).
  • GitHub = a cloud photo album the kitchen can sync with.
  • Vercel = the restaurant window that serves the latest dish to guests (your phone).
  • Cursor = your notebook + a calm sous-chef who reads the recipe with you.

2. What is a repository (“repo”)?

A repository is a project folder that Git is watching. It usually lives on your computer and has a twin on GitHub with the same history.

Example: E:\Amigo on your PC is your local repo. github.com/claricemo/amigo is the online copy. They talk through push (send changes up) and pull (bring changes down).

You need a repo so you never have twelve mystery copies of “Amigo-final-really-final.” One history, one truth.

3. Why Git?

Git remembers snapshots of your files and lets you say “this change is one saved step” (a commit). If something breaks, you can step back.

Function: history + undo + “what did I change?”

Basic use: after editing files → stage (pick what goes in this snapshot) → commit (save snapshot with a short note) → push (send to GitHub).

You need it because Amigo will grow. Without Git, one wrong delete can ruin a weekend.

4. Why GitHub?

GitHub stores your repo on the internet, backs it up, and lets tools like Vercel read your code when you want automatic deploys.

Function: online home for claricemo/amigo, issues, and collaboration if you ever invite someone.

Basic use: create account → create repo → connect your computer’s Git to that URL → push.

You need it because your laptop can fail; GitHub is the backup and the bridge to hosting.

5. Why Cursor?

Cursor is a code editor built like VS Code, with AI help inside the same window where you edit files. You can ask it to explain an error, sketch a small change, or follow rules you wrote for the project (like your Amigo master prompt).

Function: edit code + get focused help without juggling ten browser tabs.

Basic use: open folder E:\Amigo → chat or inline edits → save files → commit in Git when happy.

You need it (for this workflow) because Amigo is built faster and calmer with an editor that understands the whole folder—not because Cursor runs the live website (it doesn’t).

6. Why Vercel?

Vercel takes your Next.js project and builds a public website at a URL like something.vercel.app. Your phone can open that URL even when your laptop is closed.

Function: build + host + HTTPS + optional “deploy every time you push to main.”

Basic use: connect project once → deploy → bookmark production URL. Optional: connect GitHub so each push updates the site.

You need it because Amigo is meant to be used on your phone in real life—not only on localhost.

7. Other things Amigo will need later (not all on day one)

  • Node.js / npm — runs your Next.js app on your computer (npm run dev). Comes with installing dependencies for the project.
  • .env files — secret keys live in .env.local on your machine only; never committed. .env.example lists names without real secrets.
  • Supabase (later) — database for the journal; stays in your account.
  • Anthropic API (later) — powers chat / Untangler; costs a little; keys stay server-side.

8. Which order to set up first?

Use this order so each step has something to plug into:

  1. GitHub account + create the empty repo amigo (if you haven’t).
  2. Git on your PC + clone or connect your folder to https://github.com/claricemo/amigo.git.
  3. Cursor → open E:\Amigo as the workspace.
  4. Node → in the project folder, run npm install once so dependencies exist.
  5. Run locally → npm run dev → check http://localhost:3000.
  6. Vercel account → import / link the GitHub repo → get a live URL.
  7. Optional but nice: connect GitHub to Vercel so pushes deploy automatically (private repos need GitHub → Vercel app permission).
  8. Later phases: Supabase, API keys, passphrase login—when the specs say so.

9. How to “access” each thing (where to click)

  • Your code folder: File Explorer → E:\Amigo.
  • GitHub repo in browser: https://github.com/claricemo/amigo
  • Vercel dashboard: https://vercel.com/dashboard → pick team → project amigo.
  • Live site: your production URL from Vercel (e.g. https://amigo-theta-lovat.vercel.app—yours may differ).
  • Cursor: File → Open Folder → E:\Amigo.

10. One-page checklist

Minimum “Amigo is real online”
  1. Code in E:\Amigo, pushed to GitHub.
  2. Vercel project linked to that repo or deployed with CLI.
  3. Open production URL on your phone → see “Hello Amigo.”
